Торговый терминал «QAnt»

Система для автоматизации совершения сделок на финансовых рынках по заданным алгоритмам или в ручном режиме

  • Инвестиционным брокерам
  • Частным компаниям
  • Брокерским компаниям
  • Частным лицам

Возможности QAnt

Автоматизация

Возможность торговли без непосредственного участия человека, что позволяет исключить ошибки в принятии торговых решений из-за эмоций, невнимательности и другие “человеческие“ факторы

Больше бирж

Масштабирование на различные биржи, предоставляющие API, для охвата большего количества клиентов

Умный рост

Увеличение количества клиентов, счетов и торговых логик без привлечения дополнительных сотрудников для обеспечения процесса торговли

Функциональные характеристики

  • Автоматизированная торговля на фиатных и крипто-биржах без ограничения по времени с помощью подключаемых торговых алгоритмов.

  • Добавление подключений по API с помощью ключей логин-пароль.

  • Автоматическое восстановление после разрыва связи (переподключение).

  • Логирование всех операций. Сохранение истории всех операций, историй балансов и позиций в БД.

  • Подключение клиентов к торговым портфелям с различными характеристиками в зависимости от выбранного клиентом риск-профиля, биржи и т.д.

  • Добавление и обновление торговых портфелей (стратегий торговых ботов), включая изменение торговой стратегии.

  • Перевод (миграция) клиента на другой портфель. Остановка торговли клиента.

  • Добавление и перерасчет максимальной стоимости портфеля клиента за определенный период времени (HWM).

  • Система автоматического мониторинга инцидентов, включая обрывы связи, отклонения от расчетной торговли, резкое изменение балансов.

  • Система риск-менеджмента в различных модулях для остановки торговых ботов для предотвращения изменения позиций вне торговой логике.

Архитектура системы

Программное обеспечение включает в себя графическую оболочку (Терминал) для удобства управления счетами, заявками, роботами, а также обширную внутреннюю часть:

  • Модули обработки данных от бирж и преобразования внутренних команд;
  • Модули работы с базой данных;
  • Распределенную систему мониторинга инцидентов;
  • Модуль оповещения об инцидентах и состояниях счетов;
  • Библиотеку торговых роботов.

Для возможности гибкого развития системы путём добавления новых модулей, а также из-за ограничений Python на использование CPU было принято решение использовать модульную (микросервисную) архитектуру с обменом данными между модулями с помощью сокетов ZeroMQ.

Требования к эксплуатации системы

Установка и эксплуатация системы

Приложение для управления клиентами и торговлей системы QAnt - Скачать

Требования к операционной системе: Windows 8.1 и более поздние версии

Запуск:

  • переместить директорию .ssh в домашнюю директорию пользователя;
  • исправить путь до приватного ключа SSH в файле settings.ini (key_file);
  • запустить qterminal
  • ввести логин и пароль

Минимальные системные требования

  • ОС: Windows 7 и выше, Linux Qt 5.15 и выше, Mac OC 10.15 и выше;
  • Экран: Разрешение 1024х768 Пикс;
  • Процессор: Intel/AMD-совместимый x64, с частотой 2 ГГц;
  • Видеокарта: 512 Мб;
  • ОЗУ: 75 Мб;
  • Язык – Python;
  • Объем программы (место на диске) – 130 МБ

Резервное копирование данных

Ежедневное резервное копирование данных включает в себя:

  • Создание резервной копии файлов Системы;
  • Создание резервных копий БД.

Настройка регулярного резервного копирования БД выполняется с использованием специализированных утилит СУБД и инструментов ОС.

Поддержание жизненного цикла Системы обеспечивается за счет её сопровождения и проведения обновлений в соответствии с собственным планом разработки.

Неисправности, выявленные в ходе эксплуатации Системы, могут быть исправлены следующим образом:

Процесс разработки

  • Разработка новых модулей и функций;
  • Развитие и оптимизация текущих модулей и функций;

  • Исправление найденных ошибок;
  • Разработка документации и инструкций

Модернизация/обновление ПО

Выпуск новых версий осуществляется в соответствии с собственным планом разработки, а также в случае выявленных проблем в ходе эксплуатации программного обеспечения у конечных потребителей
